## Failure
- Failed step: `build_image` → Cloud Build step #8 `frontend-build-push` exited 1.
- Terminating error (frontend production build, `craco build`):
  ```
  Failed to compile.
  [eslint]
  src/components/ProjectDialog.jsx
    Line 228:43:  React Hook "useState" is called conditionally. React Hooks must be
    called in the exact same order in every component render. Did you accidentally
    call a React Hook after an early return?  react-hooks/rules-of-hooks
  ```
  CRA/craco treats ESLint **errors** as build failures, so this aborts the production build (and therefore the whole deploy).

## Root cause
In `frontend/src/components/ProjectDialog.jsx`, the new "Jours supplémentaires (non consécutifs)" state hook was added in the **middle of the component body, after an early return**:

- Line 155: `if (!project || !form) return null;`  ← early return
- Line 228: `const [newExtraDate, setNewExtraDate] = useState("");`  ← hook declared AFTER the early return

React's Rules of Hooks require every hook to run unconditionally, in the same order, on every render. A `useState` placed after `return null` is skipped whenever `!project || !form`, so its call order varies between renders → `react-hooks/rules-of-hooks` (error level) → build fails. The other ~12 hooks (`useState`/`useEffect`/`useRef`) in this component are all correctly declared before line 155; only this new one was misplaced.

## Fix (exact change)
Move ONLY the `useState` declaration above the early return. The helper functions `addExtraDate` / `removeExtraDate` are plain functions (not hooks) and can stay where they are.

In `frontend/src/components/ProjectDialog.jsx`:

1. **Delete** the hook from its current spot (~line 228, just above `addExtraDate`):
   ```js
   // iter213 : gestion des jours supplémentaires (non consécutifs)
   const [newExtraDate, setNewExtraDate] = useState("");   // <-- remove THIS line only
   const addExtraDate = () => { ... };                      // keep
   const removeExtraDate = (d) => { ... };                  // keep
   ```

2. **Add** it next to the other hooks, immediately after the existing `removeChoiceOpen` state and BEFORE `if (!project || !form) return null;` (~line 134):
   ```js
   const [removeChoiceOpen, setRemoveChoiceOpen] = useState(null); // { name } | null
   const [newExtraDate, setNewExtraDate] = useState("");           // <-- moved here
   ...
   // (derived useMemo etc.)
   if (!project || !form) return null;                             // early return now AFTER all hooks
   ```

Net effect: all hooks execute unconditionally before any early return; `addExtraDate`/`removeExtraDate` continue to reference `newExtraDate`/`setNewExtraDate` from the enclosing scope unchanged.
