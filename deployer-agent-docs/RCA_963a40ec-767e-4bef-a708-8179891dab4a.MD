## Terminating error (verbatim from build log)
```
Failed to compile.

[eslint]

  Line 609:28:  React Hook "React.useRef" cannot be called inside a callback. React Hooks must be called in a React function component or a custom React Hook function  react-hooks/rules-of-hooks
  Line 610:27:  React Hook "React.useRef" cannot be called inside a callback. ... react-hooks/rules-of-hooks
error Command failed with exit code 1.
```
CRA/craco runs ESLint at build time with `eslint-config-react-app`, and `react-hooks/rules-of-hooks` is an **error** there (unlike a local `yarn start` where it may only warn) — so the production build hard-fails.

## Root cause
The pinch/drag support added in change #3 (iter206) placed two `React.useRef(...)` calls **inside the `createPortal((() => { ... })())` IIFE callback** that renders the photo lightbox (around line 609–610 of `frontend/src/components/ProjectDialog.jsx`). Hooks may only be called at the top level of a component or custom hook — never inside a nested callback/IIFE. This violates the Rules of Hooks and ESLint blocks the build.

## Fix (verified in eph sandbox)
Move the two refs to the top level of the `ProjectDialog` component and keep the callback referencing them via `.current` (which is legal).

**In `frontend/src/components/ProjectDialog.jsx`:**

1. DELETE these two lines from inside the `createPortal` callback (were ~line 609–610):
```jsx
        const pinchState = React.useRef({ startDist: 0, startScale: 1 });
        const dragState = React.useRef({ dragging: false, x0: 0, y0: 0, sx: 0, sy: 0 });
```

2. ADD them at the component top level, immediately after the existing `galleryRef` declaration (~line 108, alongside the other `useRef`/`useState` hooks). `useRef` is already imported at line 1 (`import React, { useEffect, useRef, useState } from "react";`):
```jsx
  const cameraRef = useRef(null);
  const galleryRef = useRef(null);
  const pinchState = useRef({ startDist: 0, startScale: 1 });   // <-- add
  const dragState = useRef({ dragging: false, x0: 0, y0: 0, sx: 0, sy: 0 });   // <-- add
```

No other changes needed — the callback body already uses `pinchState.current` / `dragState.current`, which continues to work unchanged. Behaviour is identical (refs persist across the re-renders that `setZoomScale` triggers during a gesture, which is exactly why refs are required here rather than plain locals).
