## Root cause
The iter160 edit to `frontend/src/pages/Sales.jsx` (inside the `filtered = useMemo(...)` block) left an **orphaned, unclosed declaration**. Original lines 396–398 were:

```js
396:    const STATUS_ORDER = [
397:    // (STATUS_ORDER historique conservé dans le fallback ci-dessous — iter160)
398:    const _UNUSED_ORDER = [
```

Line 396 opens `const STATUS_ORDER = [` and never closes it; the parser then hits `const` on line 398 inside what it thinks is an array literal → `Unexpected token (398:4)`. It is a leftover stub: the *real*, intended `STATUS_ORDER` is correctly (re)defined ~20 lines later as:

```js
const configuredOrder = (statuses || []).map((s) => s.value);
const STATUS_ORDER = configuredOrder.length ? configuredOrder : STATUS_ORDER_FALLBACK;
```

So lines 396–397 are pure dead debris. (Note: had 396 merely been closed instead of deleted, it would then collide with the later `const STATUS_ORDER` as a duplicate declaration — deletion is the correct fix, not repair.)

## Fix (verified)
Delete the two orphaned lines 396–397 of `frontend/src/pages/Sales.jsx`:

```
-    const STATUS_ORDER = [
-    // (STATUS_ORDER historique conservé dans le fallback ci-dessous — iter160)
```

Resulting region (well-formed): the `// Group order requested by user…` comment is immediately followed by `const _UNUSED_ORDER = [ … ]; void _UNUSED_ORDER;`, then `STATUS_ORDER_FALLBACK`, `configuredOrder`, and the single real `const STATUS_ORDER = …`.
